# Ship agent skills that teach frit's own workflow

## Goal

Make frit ship the skill that teaches an agent to use frit. A new
`frit skills` verb writes a bundled Claude Code skill into a repo's
[.claude/skills](../.claude/skills), so any repo frit indexes also
carries the instructions for driving frit's discover → claim →
implement loop — without the agent's operator hand-copying prose.

## Context

frit already scaffolds one file into a repo: `frit init` writes
`.frit.yml` from a `go:embed`-free constant in
[internal/repocfg](../internal/repocfg/template.go), refusing to
clobber an existing file unless `--force`, and reporting the written
path through [report.Init](../internal/report/meta.go). That is the
exact shape a skill installer wants.

The knowledge itself already exists as prose in
[CLAUDE.md](../CLAUDE.md): the discovery verbs, the atomic claim, the
red/green/commit rule, the plan-upkeep rule. What is missing is a way
for that knowledge to travel *with the tool*. It should reach the
repos frit works on as a skill an agent loads on its own, not a
paragraph a human pastes.

The skills themselves are adapted from the plan-lane convention
proven in a sibling project: `plan-pick`, `plan-phase`, `plan-new` and
`plan-sync`, retargeted onto frit's own verbs. Each is written tight —
a skill loads into a working session, so every line is paid for.

One content detail is load-bearing. A shipped skill lands where `frit`
is a binary on `PATH`, so its commands read `frit pick`, not
`go run ./cmd/frit pick`. The `go run` form is correct only inside
this source checkout; the shipped text names `frit` and notes the
source-checkout form once.

This also lets frit dogfood: frit's own [.claude/skills](../.claude/skills)
becomes the output of `frit skills`, not a hand-kept copy that drifts
from what ships.

## Non-goals

- No new mutation semantics. Writing skill files is scaffolding, the
  same class as `frit init`; it is not the claim and touches no ref.
- No skill runtime. frit writes the markdown and reports the paths; it
  never invokes a skill or reads what an agent does with it.
- Not a plan for a suite of skills. One skill — the plan-work loop —
  ships now; the package is shaped to hold more later.

## Phase 1: bundle and install the skill

A new `internal/skills` package owns the bundled skill and lays it
down. The skill markdown lives under the package (e.g.
`internal/skills/assets/work-a-plan/SKILL.md`) and is pulled into the
binary with `go:embed`. `Install(repoDir string, force bool)
([]string, error)` writes each embedded skill to
`.claude/skills/<name>/SKILL.md` under repoDir, creating directories,
refusing to clobber an existing file unless force, and returning the
written paths sorted. Mirror `repocfg`'s `ErrExists` and force rule.

## Phase 2: the `frit skills` verb and its report

Add a `skills` command — `frit skills [dir] [--force]` — that calls
`skills.Install` and, under `--json`, emits a `report.Skills` document
carrying the written paths. The list is `[]` never null, every key
present, per the JSON contract. Record `internal/report/testdata/skills.json`
with `go test ./internal/report -update` and read the diff.

## Phase 3: a mdsmith kind that keeps skills tight

A skill is read under time pressure and loaded into a session, so it
must stay skimmable and cheap. Add a `skill` kind to
[.mdsmith.yml](../.mdsmith.yml) that keeps readability on and caps the
line count hard, and lints both the canonical assets and the installed
copies. Scope the `name` uniqueness to the assets, since the dogfooded
copies carry the same names by design.

## Phase 4: dogfood and document

Regenerate frit's own [.claude/skills](../.claude/skills) from the
bundle so the repo carries exactly what ships. Document the verb and
the skill kind in [CLAUDE.md](../CLAUDE.md), and run
`mdsmith fix PLAN.md` so the index re-renders. All markdown, including
the embedded skills, passes `mdsmith check .`.

## Follow-up (not this plan)

The skills still spell out steps that frit could emit itself. A later
plan can enrich `frit next`/`frit show` to print the phase body, tier
and gate an agent needs, so a skill leans on frit's output instead of
prose — fewer tokens, one source of truth. Tracked separately.

## Execution

Tier is per phase, set by the most demanding ingredient.

| Phase              | Design | Implement | Gate that catches a wrong answer                                    |
| ------------------ | ------ | --------- | ------------------------------------------------------------------- |
| 1 bundle & install | sonnet | sonnet    | test that Install writes the tree and refuses to clobber sans force |
| 2 verb & report    | sonnet | sonnet    | golden skills.json with paths as `[]`, and a JSON-vs-table test     |
| 3 skill kind       | sonnet | sonnet    | `mdsmith check .` fails a skill over the line cap or a missing name |
| 4 dogfood & docs   | sonnet | sonnet    | `mdsmith check .` clean; shipped skills == repo's .claude/skills    |

## Tasks

1. `internal/skills`: embed the skills and write `Install`, red first —
   a test that it writes `.claude/skills/plan-pick/SKILL.md`, returns
   the paths, and returns `ErrExists` on a second run without force
2. Write the suite — `plan-pick`, `plan-phase`, `plan-new`,
   `plan-sync` — on frit's verbs, tight, `frit`-on-PATH with a
   source-checkout note
3. Add the `frit skills` command and `report.Skills`; record the golden
   JSON and read the diff
4. Add the `skill` kind to `.mdsmith.yml`: readability on, a hard line
   cap, both locations linted, name uniqueness scoped to the assets
5. Regenerate frit's own `.claude/skills` from the bundle; document the
   verb and the kind, and run `mdsmith fix PLAN.md`

## Acceptance Criteria

- [x] `frit skills` writes the plan-pick/phase/new/sync skills into a
      repo and reports every path
- [x] A second run without `--force` refuses to clobber; `--force`
      overwrites
- [x] `frit skills --json` carries the written paths, `[]` never null,
      every key present
- [x] Every shipped skill names `frit`, not `go run ./cmd/frit`, and
      passes `mdsmith check .`
- [x] The `skill` kind fails a skill over the line cap or missing a
      `name`/`description`, and lints both the assets and the copies
- [x] frit's own `.claude/skills` matches what `frit skills` writes
- [x] All tests pass: `go test ./...`
- [x] `go tool -modfile=tools/go.mod golangci-lint run` is clean
