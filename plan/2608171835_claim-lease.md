# The claim lease

## Goal

Give frit its own atomic claim. Then `frit start` can stand a lane up
without a second tool that is not always installed. The claim is a
git-ref lease: an empty marker commit, pushed to the shared remote with
`--force-with-lease`. That push is the one operation that decides a
race. Two machines reaching for the same plan resolve to one winner.

## Context

frit was read-only by construction, and delegated every mutation. That
boundary bought a clean split — frit indexes and displays, herdr owns
panes, and the claim lived in a separate registry. The registry it
delegated to is a Zig tool that is not on every machine frit runs on,
and a dispatch ladder that cannot claim is a ladder missing its top
rung.

So frit grows the one mutation it cannot borrow: the claim. It keeps
delegating the rest — herdr still owns the worktree and the pane, and a
claim here mints the ref and stops, handing the checkout to
`worktree.create` when rung 3 arrives. frit becomes the writer of the
hold it already reads, and owns no second thing.

The lease is not a local branch. A local branch races: two machines
each make one and neither knows. The atomic form is an empty marker
commit — same tree as the base, parented on it, so it dates the claim
and records which machine took it without touching the plan file — then
`push --force-with-lease=<ref>:` to the shared remote. The empty lease
expectation means the push succeeds only if no claim ref exists yet;
the loser's push is rejected, and the loser drops its local ref so a
retry is clean. That rejection is the race being decided, and it is why
the lease must go through the remote, not stay on disk.

The branch name is derived, never stored: `plan/<id>-<slug>`, from the
plan file. It is the shape `.frit.yml`'s hold pattern already matches,
so a lease frit writes is a hold frit reads. The check before the write
— deps done, nobody holds — is the readiness rule `internal/discovery`
already computes for `ready`. The claim refuses an unpickable plan
rather than leasing it.

## Phase 1: the base and remote a lease needs

Add `remote` and `base` to the per-repository `.frit.yml`. A lease is
pushed to a remote and dated against a base, and neither is frit's to
guess fleet-wide. The defaults are the common case. The remote is
`origin`. The base is resolved by the same `origin/HEAD → main → master
→ HEAD` cascade `internal/gitobj` already walks. So a repository on the
convention needs no new config at all.

## Phase 2: mint the lease

Ship an `internal/claim` package that writes the lease and nothing
else. It derives the branch, resolves the base sha and its tree, writes
the empty marker commit with `commit-tree`, `update-ref`s the local
claim, and pushes it with `--force-with-lease`. A rejected push is the
lost race. Drop the local ref, and report the holder rather than the
git error. It is pure git plumbing behind the runner seam
`internal/gitwt` already defines. So the race is driven red and green
against a real temporary remote.

## Phase 3: the claim command

Ship `frit claim <id>`: refuse a plan that is unpickable — a dependency
unmet, or a lane already holding it — and otherwise mint the lease and
report the branch and base it wrote. `--json` carries the same, so an
agent can claim and read back the branch it now holds. The claim mints
the ref and stops; the worktree and the pane stay herdr's, reached by
the dispatch ladder's rung 3.

## Execution

Tier is per phase, set by the most demanding ingredient.

| Phase               | Design | Implement | Gate that catches a wrong answer                             |
| ------------------- | ------ | --------- | ------------------------------------------------------------ |
| 1 base and remote   | sonnet | sonnet    | test the defaults resolve with no config, and config wins    |
| 2 mint the lease    | opus   | opus      | test two claims race and exactly one wins, loser rolled back |
| 3 the claim command | opus   | sonnet    | test an unpickable plan is refused, a pickable one leased    |

## Non-goals

- No worktree, no pane. The claim mints the ref and stops. The checkout
  is herdr's `worktree.create`, reached by the dispatch ladder, so
  herdr keeps owning panes and worktrees.
- No handoff or adopt. Moving a lane between machines is the multi-host
  fan-out plan's work, where remote presence first arrives.
- No release in this plan. Dropping a claim is the inverse verb and its
  own concern; this plan is the mint, not the whole lifecycle.
- No plan-file edit. The 🔲→🔳 flip rides the first real commit, not the
  claim; the marker is empty on purpose so it never conflicts with a
  regenerated catalog.
